## 二、数据流

```
config/config_v1.xlsx
        │  work/export_map_config.py  （openpyxl 只读）
        ▼
   GAME_DATA (JSON)
        │  正则替换 /*CONFIG-DATA-START*/ … /*CONFIG-DATA-END*/
        ▼
   web/index.html  ──► 浏览器直接执行
```

- 网页上的「**刷新配置**」按钮 → `GET /api/refresh` → 服务器跑一次 `export_map_config.py` → 返回 `{ok, log}` → `location.reload()`。
- **index.html 是产物也是源码**：JS 逻辑手写维护，只有标记块内的 `GAME_DATA` 会被脚本整体覆盖。改 JS 不会被导出脚本冲掉，但**改 xlsx 必须重新导出**才会生效。

### 导出脚本的裁剪规则（重要）

导出时只保留「被引用到的数据」，所以 xlsx 里大量内容不会进网页：

| 数据 | 保留条件 |
|---|---|
| `heroes` | tag ∈ `configValue.initTeamList` |
| `monsters` | 被 `battleScene` 引用 |
| `skills` | 被上述英雄或怪物的 `skillList` 引用，**并沿 `subSkill`/`triggerSubSkill` 引用闭包带出全部子技能行** |
| `maps` | `map` 页签去重后的 (mapTag, tier) |
| `points` | `mapPoint` 页签全部行 |

> 想让某个英雄出现在选人界面，必须把它的 tag 加进 `configValue.initTeamList`，否则不会导出。
> 子技能行不需要挂进任何 `skillList`，只要被主技能的 `subSkill`/`triggerSubSkill` 引用即可随之导出。

## 三、配置表结构（config_v1.xlsx）

共 10 个页签。**列顺序是按「当前导出脚本读取的物理位置」记录的，插列/删列会直接改坏导出，务必小心。**

### 3.1 `configValue` — 全局开关

列：A `tag` / B 说明 / C `content`。导出读 `row[0]` 与 `row[2]`。

| tag | 当前值 | 作用 |
|---|---|---|
| `initMapTier` | `1` | 起始章节 |
| `initTeamSize` | `3` | 选人上限（选满才出击） |
| `initTeamList` | `longswordKnight,greatswordKnight,martialArtist,shieldOfficer,blazeMage` | 可选英雄池（逗号分隔） |
| `battleMap` | JSON 字符串 | 敌方站位区块，见 3.6 |

### 3.2 `hero` — 英雄表（58 行 / 19 列）

| 列 | 索引 | 字段 | 说明 |
|---|---|---|---|
| A | 0 | `tag` | 英文驼峰，全表主键 |
| B | 1 | 中文名 | 导出为 `name` |
| C | 2 | `class` | fighter / tank / ranger / mage / priest / monster |
| D | 3 | `tier` | 1/2/3，当前仅展示用 |
| E–J | 4–9 | `slot1Type`…`slot6Type` | 6 个骰面颜色：red/blue/green/yellow |
| K–P | 10–15 | `slot1Num`…`slot6Num` | 6 个骰面对应点数 |
| Q | 16 | `baseHp` | 基础血量 |
| R | 17 | `baseShield` | 基础护甲 |
| S | 18 | `skillList` | 技能 tag，逗号分隔 |

导出结构：`{tag: {name, cls, baseHp, baseShield, slots:[[type,num] ×6], skills:[tag…]}}`

职业中文名与 emoji 由前端 `CLASS_INFO`（index.html:615）映射，**不在表里**。

### 3.3 `monster` — 怪物表（5 行 / 7 列）

A `tag` / B 中文名 / C `class` / D `tier` / E `baseHp` / F `baseShield` / G `skillList`。
导出结构同 hero，但**没有 slots**（怪物不投骰子）。

### 3.4 `skill` — 技能表（v2：26 列结构化字段）

> v2 起 N–Z 列为结构化字段（旧版 N 列之后的文字注释已废弃）。字段含义另见用户提供的《skill配置字段说明.md》。

| 列 | 索引 | 字段 | 说明 |
|---|---|---|---|
| A | 0 | `tag` | `{heroTag}_skill{N}`；子技能 `_sub` 后缀 |
| B | 1 | 角色名 | 卡面标题（可能与 hero 表中文名不一致） |
| C | 2 | `skillName` | 导出为 `name` |
| D | 3 | `skillDesc` | 导出为 `desc`，卡面与选人卡展示 |
| E | 4 | `skillType` | skill1/skill2…；子技能行填 `sub`（**引擎按引用解析，不检查此列**，实测有 sub 行填 skill1） |
| F | 5 | `skillCost` | `"red,3"` 或 `"blue,1;green,2"`；`null` = 无消耗 |
| G | 6 | `skillCostDesc` | 消耗中文描述（显示用），未导出 |
| H | 7 | `useType` | `choose`（玩家点选）/ `auto`（自动释放）/ `null`（sub 行） |
| I | 8 | `targetType` | 见 3.5 |
| J | 9 | `targetPosion` | 范围偏移 `"dcol,drow;…"`，见 3.5 |
| K | 10 | `dmg` | 基础伤害 |
| L | 11 | `dmgShieldPara` | 护甲加成系数 |
| M | 12 | `shield` | 赋予护甲 |
| **N** | 13 | `atk` | 赋予攻击力（永久，本局有效），伤害公式见 5.1 |
| **O** | 14 | `combo` | 本技能额外命中次数 |
| **P** | 15 | `randTargetCount` | `meleeAndRand` 系列的随机目标数，默认 1 |
| **Q** | 16 | `modSkillTag` | 要修改的目标技能 tag；非空 = 本行为「技能强化器」 |
| **R** | 17 | `modType` | `combo`（加连击）/ `randTarget`（加随机目标）/ `charge`（加充能） |
| **S** | 18 | `modVal` | modType 对应增量 |
| **T** | 19 | `usePerRound` | 每回合可用次数，默认 1；「充能1」类技能填 2 |
| **U** | 20 | `trigger` | `kill`（每次击杀触发）/ `firstKillInRound`（回合首杀） |
| **V** | 21 | `triggerLimit` | 每回合触发上限 |
| **W** | 22 | `triggerSubSkill` | 触发时调用的子技能 tag |
| **X** | 23 | `subSkill` | 主技能结算后**必然**调用的子技能 tag |
| **Y** | 24 | `debuffType` | `wound`（重伤）/ `shatter`（破碎） |
| **Z** | 25 | `debuffVal` | 负面状态强度 |

导出结构：`{tag: {tag, name, desc, cost, skillType, useType, targetType, targetPosion, dmg, dmgShieldPara, shield, atk, combo, randTargetCount, modSkillTag, modType, modVal, usePerRound, trigger, triggerLimit, triggerSubSkill, subSkill, debuffType, debuffVal}}`（空值归 0/""）。

消耗解析（export:88-95）：按 `;` 拆、每段按 `,` 拆成 `[color, num]`；`null` 段跳过 → 空数组 = 无条件解锁。

**子技能行规则**（引擎 `runSubSkill`，1225）：
- 不挂 `skillList`，只被 `subSkill`/`triggerSubSkill` 引用；导出脚本按引用闭包带出。
- `targetType=inherit` → 继承主技能（或击杀触发时被击杀者）的目标，再按本行 `targetPosion` 展开；`targetType` 留空 → 默认自身。
- 行内可有自己的 `dmg`/`shield`/`atk`/`debuffType`/`debuffVal`/`modSkillTag` 等，与主技能字段无关。
- 引擎对引用不存在、字段缺失均容错（跳过并打日志）。

### 3.6 `configValue.battleMap` — 敌方站位区块

JSON：`{"battle": [[x,y]…], "battleHigh": [[x,y]…]}`
坐标含义：**`[x=行, y=列]`**，行 1 = 最靠近我方，列 1 = 最左。

- `battle`：13 格（第 1/2 行各 5 格 + 第 3 行 2–4 列）
- `battleHigh`：15 格（3 行 × 5 列满格）
- 前端按 `pointType` 取：`battle` → `battle`，其余（`battleHigh`/`battleBoss`）→ `battleHigh`（index.html:887）。**BOSS 无专属区块。**

### 3.7 `battleScene` — 敌军阵容（7 行 / 5 列）

A `tag` / B `battleScene`（场景档位 tag）/ C `munster`（怪物 tag）/ D `x` / E `y`。

> ⚠️ **坐标系陷阱**：本表 `x = 列`、`y = 行`，与 `battleMap` 的 `[行, 列]` **相反**。
> 前端 `openBattle` 用 `key = r.y + ',' + r.x`（index.html:899）转换成统一的 `"行,列"`。

当前两档：`battle1` = 狼(行1列2)/山贼(行1列4)/山贼弓手(行1列1)；`battle2` = 狼(行2列3)/山贼(行2列5)/山贼弓手(行2列1)。

### 3.8 `map` — 地图 tier（10 行 / 2 列）

A `mapTag` / B `tier`。**mapTag 向下填充**（空单元格沿用上一行的 tag），去重后得到 (mapTag, tier) 列表。
所以同一张地图挂多个 tier 时，连续写多行即可。

### 3.9 `mapPoint` — 地图格点（59 行 / 12 列）

A `tag` / B `mapTag` / C `pointNum`(整数) / D `pointType` / E `battleContent` / F–I `reward1..4` / J `extra`。

- `pointType` 取值见 `$type` 页签：battle / battleHigh / battleBoss / randWeapon / randArmor / coin / rock / start。
- `battleContent`：战斗场景档位，逗号分隔（如 `battle1,battle2`），进入时**等概率随机抽一档**。
- `reward` 格式 `"类型,值"`，如 `exp,9`、`coin,10`、`randWeapon,q3`。
- `extra`：目前只有 `shop`。
- 只有 `pointNum` 为整数且 `mapTag` 非空的行会被导出；**编号跳号 = 该格不存在**（26/30/31/32 未配）。

### 4.6 Key 规则（贯穿全文件，改代码前必读）

| 侧 | key 格式 | 例 |
|---|---|---|
| 我方 | `'O' + idx`（idx 0–5 = 槽位） | `O0`（1 号位）、`O5`（6 号位） |

  背后定义为远离对方：敌方 `row + drow`，我方 `row - drow`（`offsetKey`，1019）。

## 五、核心机制实现口径

### 5.1 伤害与护甲（v2 口径）

```js
// calcDmg (1045)
dmgPerHit = sk.dmg + sk.dmgShieldPara * caster.shield + caster.atk  // 护甲只加成不消耗；atk 参与结算
// applyDamage (1057)：再叠目标 debuff
bonus = target.debuff.wound + (破碎层数>0 ? shatterVal（消耗1层） : 0)
total = dmgPerHit + bonus
absorbed  = min(target.shield, total)
target.shield -= absorbed
target.hp = max(0, target.hp - (total - absorbed))
```

护甲归属：`ENEMY_TARGET = ['melee','meleeRand','any','meleeAndRand','meleeAndRand2']`（855）。
- targetType ∈ 该集合 → 护甲加给**释放者自己**（敌方向技能口径）
- 否则（`self` / `friend` / `friendMelee` / `friendAndSelf` / `selfAndfriendMelee`）→ 加给**受影响目标**

> 副作用：我方若配一个 `melee` + `shield>0` 的技能，护甲也会加到自己身上。

### 5.2 技能 v2 机制（applySkillEffects 1095）

结算顺序：范围展开 → **连击伤害** → **护甲** → **攻击力** → **debuff** → **强化器**，然后 `releaseSkill`（1250）接 **subSkill** 与**击杀触发**。

| 机制 | 口径 | 实现位置 |
|---|---|---|
| 连击 combo | 实际命中 = 1 + `sk.combo` + 强化器存量；每次同伤害独立结算，目标死亡后剩余命中落空 | `comboOf` (1043) + `applySkillEffects` 伤害循环 |
| 攻击力 atk | 受影响的每个存活目标永久 +N；参与其所有伤害技结算（见 5.1）；格子显示 ⚔ 徽标 | `applySkillEffects` 1126 |
| 充能 usePerRound/charge | 每回合可用次数 = `usePerRound`(默认1) + charge 存量；choose 技能用 `uses` 计数、释放后 +1；auto 技能无视（每回合固定一次） | `maxUses/usesOf` (1049/1053)、`onChipClick`/`doRelease` |
| 强化器 modSkillTag | 改本单位另一技能：`combo`/`randTarget` 每单位对同一目标技**只生效一次**（auto 每回合重放不叠加，`modSet` 去重）；`charge` **逐次累积**（击杀触发充能跨回合叠加）；可与同行 shield/atk 共存 | `applyMod` (1190)、`finalTargets` 随机数 |
| 重伤 wound | 目标每次受到伤害 +N，本回合内有效（不消耗） | `applyDebuff` (1172) |
| 破碎 shatter | 目标接下来 N 次受到的伤害每次 +N（每次消耗 1 层），本回合内有效 | `applyDamage` 1061 |
| 击杀触发 trigger | 每次击杀逐次触发（被杀者 = `triggerSubSkill` 的 inherit 目标），受 `triggerLimit` 每回合上限；`firstKillInRound` 语义同 kill+上限1；触发的击杀**递归连锁** | `processKillTriggers` (1227) |
| 子技能 subSkill | 主技能结算后必然执行；`targetType=inherit` 继承主目标；未填 targetType 默认自身；可链式引用 | `runSubSkill` (1209) |
| 随机目标 randTargetCount | `meleeAndRand`/`meleeAndRand2` 的随机目标数 = P 列 + 强化器存量（`meleeAndRand2` 为旧枚举，同口径处理） | `finalTargets` (982) |

> **回合边界**：`uses`/`trigUsed`/`debuff` 都在 `startOursStage`（1328）清空（双方）；`atk`/`mods`/`modSet` 永久保留到战斗结束。

### 5.3 骰子

- 每英雄掷 `1 + rand(6)`，取 `hero.slots[n-1] = [type, num]`。
- `diceTotals()` 按颜色累加 num；`skillUnlocked(cost, totals)` = 每种颜色总量 ≥ 需求。
- **释放不消耗**点数，同回合可多次释放（每个 `choose` 技能按 5.2 的次数上限，`auto` 每回合自动一次）。
- 怪物 `cost` 为 `null` → 空数组 → 恒解锁；`enemyAim` 里用 `skillUnlocked(cost, {})` 保证这条成立。

### 5.4 回合流程

```
startOursStage()
  ├─ 重置所有 ours: acted=false, uses=∅, trigUsed=∅, debuff=null（敌方 debuff 同步清）
  ├─ autoReleaseSide('ours')           我方 auto（含强化器行，uses 计数）
  ├─ enemyAim()                        敌方锁定（每回合重瞄）
  ├─ 无可用 choose 技能的单位 → acted=true
  └─ 全部 acted → enemyPhase()
doRelease()                            玩家释放
  └─ uses[st]++; acted = !hasUsableChoose(u); 全部 acted → enemyPhase()
enemyPhase()
  └─ 遍历 battle.aims 逐个 releaseSkill(lockedTargets) → nextTurn()
nextTurn() → phase='dice' → rollAllDice()
```

**关键不变量**：
- `battle.ours[idx]` 必须与 `battle.deploy[idx]` 对齐（拖拽换位时两者一起交换）。
- `enemyPhase` 用 `try/finally` 保证 `inputLock` 一定恢复，否则左栏永久失效。
- `releaseSkill` 内若有单位死亡，`checkEnd` 延后 1s（1267）等死亡动画播完。
- 子技能 / 触发链全部在 `releaseSkill` 内同步执行完才渲染与判胜负。

### 5.5 预览系统一致性

三处预览必须与实际结算同口径，改 `applySkillEffects` 时**三处都要改**：

| 位置 | 函数 | 用途 |
|---|---|---|
| 我方选技悬停 | `calcPreview` (1938) | 单次技能预览（连击乘算 + 目标 debuff 加成） |
| 敌方瞄准常驻 | `aimPreview` (1367) | 汇总多条瞄准 |
| 敌方悬停 | `showEnemyPreview` (2060) | 按 casterKey 汇总后再叠加 |

三者都用同一个 `expandTargets(casterKey, sk, targets)` 展开范围和同一个伤害公式（`calcDmg`）。

> 预览近似：破碎加成按"未消耗"估算，多次命中时的逐层消耗不模拟。

### 5.6 渲染约定

- 每次 `renderBattle()` 都会 `innerHTML=''` 重建整个战场，因此：
  - SVG 覆盖层（`#aimLinesSvg` / `#skRangeSvg`）随重建消失，无需手动清理 `#skRangeSvg`；`clearAimLines` 只删 `path`。
  - 所有状态必须存在 `battle` 对象里，**不能依赖 DOM 上的临时状态**。
- 左栏按阶段渲染：`renderDeployPanel` / `renderDicePanel` / `renderFightPanel`。
- 空槽位用 `emptySlotRow(i)` 占位，保证 1–6 号位行高固定。
