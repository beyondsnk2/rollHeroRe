## 二、数据流

```
config/config_v1.xlsx
        │  work/export_map_config.py  （openpyxl 只读）
        ▼
   GAME_DATA (JSON)
        │  正则替换 /*CONFIG-DATA-START*/ … /*CONFIG-DATA-END*/
        ▼
   web/index.html  ──► 浏览器直接执行
```

- 网页上的「**刷新配置**」按钮 → `GET /api/refresh` → 服务器跑一次 `export_map_config.py` → 返回 `{ok, log}` → `location.reload()`。
- **index.html 是产物也是源码**：JS 逻辑手写维护，只有标记块内的 `GAME_DATA` 会被脚本整体覆盖。改 JS 不会被导出脚本冲掉，但**改 xlsx 必须重新导出**才会生效。

### 导出脚本的裁剪规则（重要）

导出时只保留「被引用到的数据」，所以 xlsx 里大量内容不会进网页：

| 数据 | 保留条件 |
|---|---|
| `heroes` | tag ∈ `configValue.initTeamList` |
| `monsters` | 被 `battleScene` 引用 |
| `skills` | 被上述英雄或怪物的 `skillList` 引用 |
| `maps` | `map` 页签去重后的 (mapTag, tier) |
| `points` | `mapPoint` 页签全部行 |

> 想让某个英雄出现在选人界面，必须把它的 tag 加进 `configValue.initTeamList`，否则不会导出。

### 3.6 `configValue.battleMap` — 敌方站位区块

JSON：`{"battle": [[x,y]…], "battleHigh": [[x,y]…]}`
坐标含义：**`[x=行, y=列]`**，行 1 = 最靠近我方，列 1 = 最左。

- `battle`：13 格（第 1/2 行各 5 格 + 第 3 行 2–4 列）
- `battleHigh`：15 格（3 行 × 5 列满格）
- 前端按 `pointType` 取：`battle` → `battle`，其余（`battleHigh`/`battleBoss`）→ `battleHigh`（index.html:877）。**BOSS 无专属区块。**

### 3.7 `battleScene` — 敌军阵容（7 行 / 5 列）

A `tag` / B `battleScene`（场景档位 tag）/ C `munster`（怪物 tag）/ D `x` / E `y`。

> ⚠️ **坐标系陷阱**：本表 `x = 列`、`y = 行`，与 `battleMap` 的 `[行, 列]` **相反**。
> 前端 `openBattle` 用 `key = r.y + ',' + r.x`（index.html:889）转换成统一的 `"行,列"`。

当前两档：`battle1` = 狼(行1列2)/山贼(行1列4)/山贼弓手(行1列1)；`battle2` = 狼(行2列3)/山贼(行2列5)/山贼弓手(行2列1)。

### 3.8 `map` — 地图 tier（10 行 / 2 列）

A `mapTag` / B `tier`。**mapTag 向下填充**（空单元格沿用上一行的 tag），去重后得到 (mapTag, tier) 列表。
所以同一张地图挂多个 tier 时，连续写多行即可。

### 3.9 `mapPoint` — 地图格点（59 行 / 12 列）

A `tag` / B `mapTag` / C `pointNum`(整数) / D `pointType` / E `battleContent` / F–I `reward1..4` / J `extra`。

- `pointType` 取值见 `$type` 页签：battle / battleHigh / battleBoss / randWeapon / randArmor / coin / rock / start。
- `battleContent`：战斗场景档位，逗号分隔（如 `battle1,battle2`），进入时**等概率随机抽一档**。
- `reward` 格式 `"类型,值"`，如 `exp,9`、`coin,10`、`randWeapon,q3`。
- `extra`：目前只有 `shop`。
- 只有 `pointNum` 为整数且 `mapTag` 非空的行会被导出；**编号跳号 = 该格不存在**（26/30/31/32 未配）。

### 4.6 Key 规则（贯穿全文件，改代码前必读）

| 侧 | key 格式 | 例 |
|---|---|---|
| 我方 | `'O' + idx`（idx 0–5 = 槽位） | `O0`（1 号位）、`O5`（6 号位） |
| 敌方 | `"行,列"`（行 1–3，列 1–5） | `1,3` = 第 1 行第 3 列 |

- `getUnit(key)` 用 `key[0] === 'O'` 区分两侧；`sideOf` / `oppoOf` 同理。
- **我方 idx ↔ 坐标**：`idx < 3` → 第 1 行（远），否则第 2 行（近）；列 = `idx % 3 + 1`（`unitPos`，1000）。
- **`targetPosion` 偏移方向**：`"dcol,drow"`，dcol 为左右，drow 为前后，**+1 = 目标背后**。
  背后定义为远离对方：敌方 `row + drow`，我方 `row - drow`（`offsetKey`，1009）。

## 五、核心机制实现口径

### 5.1 伤害与护甲

```js
dmg       = sk.dmg + sk.dmgShieldPara * caster.shield   // 护甲只加成，不消耗
absorbed  = min(target.shield, dmg)
target.shield -= absorbed
target.hp = max(0, target.hp - (dmg - absorbed))
```

护甲归属：`ENEMY_TARGET = ['melee','meleeRand','any','meleeAndRand','meleeAndRand2']`（845）。
- targetType ∈ 该集合 → 护甲加给**释放者自己**（敌方向技能口径）
- 否则（`self` / `friend` / `friendMelee` / `friendAndSelf` / `selfAndfriendMelee`）→ 加给**受影响目标**

> 副作用：我方若配一个 `melee` + `shield>0` 的技能，护甲也会加到自己身上。

### 5.2 骰子

- 每英雄掷 `1 + rand(6)`，取 `hero.slots[n-1] = [type, num]`。
- `diceTotals()` 按颜色累加 num；`skillUnlocked(cost, totals)` = 每种颜色总量 ≥ 需求。
- **释放不消耗**点数，同回合可多次释放（每个 `choose` 技能每回合各一次，`auto` 每回合自动一次）。
- 怪物 `cost` 为 `null` → 空数组 → 恒解锁；`enemyAim` 里用 `skillUnlocked(cost, {})` 保证这条成立。

### 5.3 回合流程

```
startOursStage()
  ├─ 重置所有 ours: acted=false, used=∅
  ├─ autoReleaseSide('ours')           我方 auto
  ├─ enemyAim()                        敌方锁定（每回合重瞄）
  ├─ 无可用 choose 技能的单位 → acted=true
  └─ 全部 acted → enemyPhase()
doRelease()                            玩家释放
  └─ used.add(st); acted = !hasUsableChoose(u); 全部 acted → enemyPhase()
enemyPhase()
  └─ 遍历 battle.aims 逐个 releaseSkill(lockedTargets) → nextTurn()
nextTurn() → phase='dice' → rollAllDice()
```

**关键不变量**：
- `battle.ours[idx]` 必须与 `battle.deploy[idx]` 对齐（拖拽换位时两者一起交换，1481–1485）。
- `enemyPhase` 用 `try/finally`（1261）保证 `inputLock` 一定恢复，否则左栏永久失效。
- `releaseSkill` 内若有单位死亡，`checkEnd` 延后 1s（1108）等死亡动画播完。

### 5.4 预览系统一致性

三处预览必须与实际结算同口径，改 `releaseSkill` 时**三处都要改**：

| 位置 | 函数 | 用途 |
|---|---|---|
| 我方选技悬停 | `calcPreview` (1757) | 单次技能预览 |
| 敌方瞄准常驻 | `aimPreview` (1206) | 汇总多条瞄准 |
| 敌方悬停 | `showEnemyPreview` (1874) | 按 casterKey 汇总后再叠加 |

三者都用同一个 `expandTargets(casterKey, sk, targets)` 展开范围，和同一个伤害公式。

### 5.5 渲染约定

- 每次 `renderBattle()` 都会 `innerHTML=''` 重建整个战场，因此：
  - SVG 覆盖层（`#aimLinesSvg` / `#skRangeSvg`）随重建消失，无需手动清理 `#skRangeSvg`；`clearAimLines` 只删 `path`。
  - 所有状态必须存在 `battle` 对象里，**不能依赖 DOM 上的临时状态**。
- 左栏按阶段渲染：`renderDeployPanel` / `renderDicePanel` / `renderFightPanel`。
- 空槽位用 `emptySlotRow(i)` 占位，保证 1–6 号位行高固定。
